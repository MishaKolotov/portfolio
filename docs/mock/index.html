GigaWork (opens in new tab)

in production since June 2026

A Telegram bot that finds jobs for me. It pulls postings from 18 sources, drops the wrong ones with simple rules before any model call, and has a model score the rest.

37,702
postings collected by October 2026
47 of 60
good postings (ones I applied to or the bot sent me) pass the scorer I shipped. The old one, re-run, passes 35.

One thing I caught by measuring. The bot was paying a model to score postings that had nothing to do with my work, nurses and lawyers among them: 1,365 of 4,845 paid scores in three weeks came out near zero. I added a free check on the job title that runs before any paid call.

More about GigaWork
  • I test scoring on 80 real postings labelled by outcome. After a model change I re-ran them: scores fell about 8 points and the live threshold of 60 still held.
  • Posting text reaches the model wrapped as data, as a defence against prompt injection. The agents that read it get only allow-listed tools.
  • The job queue is plain Postgres. Workers take rows with an atomic claim, with no separate queue service.
  • It also built CVs and cover letters on demand from a structured record of my whole career, with the facts pinned so nothing got invented.
  • If one model provider fails, the next one takes over. A failed provider is parked for its retry window (a circuit breaker).
  • 11 LLM-judge agents check each generated CV, and two can block it. The judges are not yet checked against human labels.
  • An e-mail application goes out only after I press Send, and never twice.
  • I measured the Batch API at 2.3 times the price of cached calls ($0.0047 against $0.0020 per posting), so I dropped it before launch.

How I work with AI agents

The setup is in my repos. I can show it on a call.

ChatGPT in my daily work since 2022, Cursor at Lumigo, Claude Code now. I write the spec and a failing test first. One agent writes the code, a second one reviews it and cannot change files.

The four rules
1
Spec before any behaviour changethe edit is blocked while the spec has open questions
2
Separate agents write, review and verifydiagnosis runs on a stronger model
3
Automatic guardsno secrets in commits, lint must pass, the turn cannot end while tests are red
4
Every guard is testedwith one case it must allow and one it must block
